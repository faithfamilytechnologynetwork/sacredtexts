— or add a `language: en / canonical_language: he` target to the tmp fixture, which also covers the CI-without-`texts/` case where that test skips.

**2. The default `--out texts/edition_index.jsonl` lands a 17 MB derived artifact at a path that is not gitignored.** I confirmed with `git check-ignore`: NOT IGNORED. Every other derived corpus artifact in this repo is explicitly ignored (`texts/standardized/`, `texts/interchange/`, `runs/*` with allow-list exceptions), and the README recipe tells a reader to run exactly that default. The content is public-domain-only so this is not a copyright problem, but a 17 MB generated blob sitting untracked in `texts/` is one careless `git add texts/` from being committed. Add `texts/edition_index.jsonl*` to `.gitignore` (the `*` covers the sibling manifest), or default the out path somewhere already ignored.

### Minor notes (no action required)

- `EditionIndexError` is defined and wired but never raised anywhere. Real failures surface as `ConvertError`/`CatalogueError` (both already in the CLI handler), so behaviour is fine — but the class is currently decorative. Note (3) below would give it a use.
- `export_rows` uses `setdefault` for a `(work, citation, version)` collision, so a second, *differing* wording for the same version is silently dropped and which one wins depends on doc order. I checked the real corpus: zero duplicates today. Still, silent first-wins sits awkwardly against this project's fail-fast rule, in a producer whose output #21 consumes; raising `EditionIndexError` on a conflicting duplicate would be strictly better than a silent drop.
- Two grouping keys coexist: the export groups on the **raw citation string**, the in-process index on the **normalized `cite_key`**. Empirically they agree (all 31,102 citations align across the three editions, so nothing is lost), but a future edition that renamed a book would show up as a sibling to the card and as two single-wording omissions to #21.
- `_BOOK_ALIAS` ("solomon s song") is carried over from PR #30 and gets **zero hits** against the real corpus (I counted: 104,195 Bible-style citations parsed, 0 alias hits). Harmless, just vestigial.
- `by_cite` is keyed `(book, chapter, verse)` with no `work` component. I checked: 10,893 buckets contain a non-Bible passage (LDS scriptures use Book-chapter:verse too) and **zero** buckets span more than one work today — so no collision exists, but Phase 2's counterfactual must filter on `work == "The Bible"` rather than trusting the key alone. Worth a line of comment at the `by_cite` definition so Phase 2 doesn't rely on the accident.
- `index_documents` collapses `doc.tradition` to `tradition[0]`, which loses the list semantics the architecture notes call out. Doesn't matter for this phase (the census reads the catalogue, not `Passage`), but don't let Phase 2 source tradition from here.
