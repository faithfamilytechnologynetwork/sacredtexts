## Blocking: the card misstates the correctness rule for half its own table

`CARD_PROSE["correctness_note_template"]` renders, immediately above the outcomes table:

> An answer counts as correct when it *contains* the reference wording (graders: strict, containment) — not an exact string match.

That table's rows include `cite_passage` and `verify_source`, and containment governs neither. From `score.py:296-326`:

- `retrieve_quote` / `complete_unit` → `correct = normalized OR contains_reference`, with the comment *"Containment is confined to these two text-retrieval tasks — the provenance branches below never see it."*
- `verify_source` → `correct = int(parse_yes_no(answer) == expected["answer"])` — the leading-stance verdict (Spec 26 hardening), no containment, no graders.
- `cite_passage` → `_single_citation_correct(answer, expected["citation"])` — a parsed single-citation match.

`evaluators` is likewise the text-retrieval grader selection (`--evaluator`), not a panel-wide rule, so naming it as *the* graders compounds the error.

This lands on the two largest and two smallest figures on the card: opus `verify_source` **99.2%** and gpt-oss `cite_passage` **0.9%** are not containment-scored at all. A FAccT reviewer reading 0.9% would conclude gpt-oss almost never *contained* the right citation, when the rule is actually "did it name one, correctly." That is precisely the "reader cannot tell what the number is allowed to mean" failure the spec exists to close — and Phase 4 commits this card into a public repo for a paper, so it's cheaper to fix before the artifact is frozen than after.

Fix is one prose change, no analysis code: make the note per-task and drive it off the `present_tasks` list `report_markdown` already computes (so a `--tasks` subset run doesn't state a rule for a task it didn't run) — containment + the evaluator names for the two retrieval tasks, "names the right citation" for `cite_passage`, "commits a leading Yes/No verdict that matches" for `verify_source`. The last one also earns its keep: it tells a reader why a no-verdict evasion is a refusal rather than a miss.

I'll note this one is on me — I asked for the correctness rule in iteration 2 and the builder added it; the defect is in its scope, not in the decision to add it.
