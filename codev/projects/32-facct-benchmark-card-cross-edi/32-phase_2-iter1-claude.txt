**Finding 1 (must fix): `scores.jsonl` ↔ `summary.json` verification is one-directional, so the card can publish numbers that exist in no score row.** `_verify_against_summary` iterates only `counts` (the scores side, facct.py:140-151), and `_outcomes` derives `by_task` from `counts` while copying `overall` straight out of `summary["models"][m]["_overall"]` (facct.py:154-182). Probed in `/tmp`:

- Dropped every `complete_unit` score row (summary unchanged): **no error**. The card silently omits the task, and its `overall` reads `1/4/1` while its own `by_task` sums to `1/3/1` — a card internally inconsistent with itself.
- Truncated `scores.jsonl` to **empty**: still **no error**, and the card reports `overall 1/4/1, accuracy 0.2` — every headline figure sourced from `summary.json` with zero score rows behind it.

That contradicts two success criteria of this phase ("every outcome count equals the corresponding count in `scores.jsonl`"; fail fast on "a `scores.jsonl` count that disagrees with `summary.json`"). Fix is small: also walk each summary `models[m]` task block (keys other than `_overall`) and require a matching `counts` entry, and derive `overall` by summing the verified per-task scores counts rather than copying `_overall` (or compare the two and raise on mismatch). Add the mirror-direction test — a dropped task and an empty `scores.jsonl` must both raise `FacctError`.

**Finding 2 (must fix, cheap): the requested-edition exclusion is untested — the test is vacuous.** `if passage.version == requested_version: continue` (facct.py:214) is the guard that keeps a correctly-quoted requested edition from being tagged `other_edition`. Neither incorrect Bible `retrieve_quote` fixture cell contains any wording of its own requested edition — cell 1's answer holds only the WEB wording (`iota kappa lambda mu`), ASV's `epsilon zeta eta theta` is absent; cell 2's `Test 2:2` exists only in KJV and its answer matches nothing. So deleting that line leaves all tests green. The plan's test plan and the spec scenario both name "an answer that contains only the *requested* edition's wording is not tagged." The `Test 5:5` fixture already has per-version distinct wordings — one extra incorrect cell whose answer carries the requested version's wording covers it. This guard also silently protects against question-vs-catalogue version-string drift, which would inflate the numerator, so it deserves a test.
