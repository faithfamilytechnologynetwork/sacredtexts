### Substantive suggestions (not spec criteria — your call / the contributor's)

1. **The card says "For this panel" but never shows the panel.** The outcomes table identifies models as `gpt-oss-20b`, `haiku`, `opus`. `summary.json`/`facct.json` carry the real identity — `anthropic/claude-haiku-5-5`, `anthropic/claude-opus-5-5`, `openai/gpt-oss-20b`, all via `openrouter.ai`, `tools: []`. A FAccT reviewer reading `facct.md` standalone cannot tell *which* Haiku or whether search was on — and tool-use is part of panel identity in this project by design, so two runs of the same model with search on/off render identical cards. `report["panel"]` is already in hand; a 4-row provider/model/tools/endpoint table would close it.
2. **The correctness rule is never stated.** The card explains refusals and coverage carefully, but not what makes an answer `correct` — containment of the reference wording (`evaluators: ["strict","containment"]`, which `facct.json` carries and the markdown drops). A reader will assume exact match, and the counterfactual section leans on containment without naming it.
3. **"English" is hardcoded while the count and versions are derived.** `counterfactual_intro_template` / `counterfactual_scope_template` say "{n} … different **English** editions" but `bible_editions` is not language-filtered. Add a public-domain Latin or Greek Bible to the pool and the prose asserts something false — the exact drift class the spec warns about. Either derive the language from the data or drop the adjective.
4. **"The four tasks" is a typed count and is not derived from the run.** A run generated with `--tasks retrieve_quote` would gloss four tasks while reporting one. Rendering the gloss list filtered by the tasks actually present in `report["outcomes"]` fixes both. Minor: the gloss order (`retrieve_quote…`) differs from the table order (alphabetical).

### Minor
