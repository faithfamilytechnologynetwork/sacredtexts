## Blocking issue: a human requirement is missing

Issue #2 has an **Addendum (human, 2026-10-11), requirement 6**:

> **Cross-run aggregate view**: a page/table that shows, for each LLM, its **most recent** result across all runs — one row per model, taken from the latest run that includes that model (per-task scores + the run id/date it came from, linking to that run's detail). This is the 'current standings' view when models are benchmarked at different times in different runs.

The spec contains nothing about it. Its Constraints copy requirements 1–5 and stop; its References even claims requirements were "copied verbatim into Constraints." I grepped the spec, `codev/state/`, `codev/specs/`, and `codev/plans/` for "cross-run", "standings", "aggregate" — the only hits are "most recent *run*" as the **selector default**, which is a different thing. Requirement 6 is a distinct view with a distinct data shape (per-model latest-run resolution across runs, requiring *all* runs' summaries loaded, not just the selected one). It needs to be in Constraints, Success Criteria, and Test Scenarios — or explicitly deferred with the architect's sign-off, not silently dropped.

## Second issue: the missing-cell path is underspecified, and the fix is sitting in the run dir

Success criteria require filtering by "failure mode (missing cell vs wrong answer)" at **per-question** granularity. But `score.py` only scores rows that exist in `answers.jsonl`, and `missing = expected_n - n` is computed from a roster. So missing questions appear in **neither** `scores.jsonl` nor `answers.jsonl` — `joinResults` iterates `scores`, so those questions cannot be listed at all from the three artifacts the spec names.

The spec's Assumption calls cell-level `missing`/`expected_n` "equivalently" derivable, but it isn't: the cell tells you *how many* are missing, not *which*. There is a clean resolution the spec misses — `runs/first-run-2026-10-11/` actually contains **`questions.jsonl`** (and `questions.jsonl.manifest.json`), which with `summary.json`'s `panel` gives the exact roster. Pick one and say so:

- name `questions.jsonl` as a fourth (optional) artifact for roster-based missing-question rows — and then update the error condition "a run missing one of the three artifacts," plus the "adding a run needs summary+scores+answers" criterion; or
- scope the failure-mode filter to cell level ("this model/task has N missing") and reword the criterion to match.

After the purge, `js-yaml`, `zod`, the TanStack Query persisters, and (depending on the deploy decision) `hono`/`@hono/node-server` are plausibly unreferenced. 5. **Minor:** `_overall` cells carry no `exact`/`normalized`/`token_f1` in the real data (only per-task cells do). The leaderboard's per-metric display, if any, should expect that.
