## Comments (non-blocking)

1. **Leniency cost is larger than the 10-sample diagnostic may reveal.** My probe shows `"It is not from this edition."`, `"This passage is not from the Qur'an."`, `"Based on my search, no."`, `"Nope."`, `"Correct."`, `"1. Yes"` all → `refused`. These are substantive verdicts leaving the accuracy denominator. The architect accepted this and coverage sits beside accuracy, so the honesty mechanism exists — but for Phase 6 I'd make the README diagnostic report **shape frequencies** (how many `parsed is None` cells open with a prose negation vs. a genuine decline), not just 10 samples. If prose-negation is a large share, verify_source accuracy is partly measuring format compliance.

2. **`classify_refusal` contract trap** (`outcomes.py:105–130`). Its docstring says verify_source is "not classified here," but passing `task="verify_source"` falls through to the final `return True` and behaves like `cite_passage`. Nothing does today, but by the project's fail-fast rule a one-line raise would make the docstring enforceable.

3. **Doc nit**: `score.py:20–23` still attributes `outcome` to `outcomes.classify_refusal` with no verify_source carve-out; lines 37–40 and `_with_outcome` get it right.

4. **`_text_key(source)` returning `None` silently drops a row from `by_text`** while it still counts in `models`/`by_tradition`, so `by_text` n need not sum to the model n with no signal. Unreachable from `generate` (`_source_dict` always emits all three), so low risk — but it's a silent fallback, and no test pins it.

5. **Phase-5 follow-through**: `_SUBMETRICS` is now an empty dict kept only for dispatch + pointer-guard, and CODE_WALKTHROUGH §3/§4 prose ("the other tasks' fixed sub-metrics live in `_SUBMETRICS`", "others require the answer to *be* a specific label") is stale.
