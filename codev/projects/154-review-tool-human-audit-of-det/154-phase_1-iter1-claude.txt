## Minor notes (not blocking)

1. **`load_sample` validates unevenly.** `format`, top keys, cell keys, task/outcome enums, text-id membership and duplicates are checked with `ReviewSampleError`, but `sample["texts"]` entries (`t["id"]`), `cells` being a list, and `strata`↔`cells` consistency aren't — a malformed file raises a raw `KeyError`/`TypeError`. Phase 4 calls this at service startup for fail-fast; it still fails fast, just with a worse message. Cheap to tighten when Phase 2/4 reuse it.
2. **Run-row access is direct** (`score["metrics"]`, `answer["question"]["source"]["work"]`). Same class: fail-loud is preserved, but `main()` only pretty-prints `ReviewSampleError`.
3. **`_text_label` multi-work path** uses `.capitalize()`, so a future hyphenated multi-work folder would render "Book of mormon". No live effect (only `encyclicals/english` is multi-work today).
4. **No guard on `--out`.** Nothing stops `--out runs/...` writing inside committed run evidence. A one-line "out must not be under `runs/`" check would protect the project's read-only-evidence invariant.
5. **Untested small paths:** `_key_rows` duplicate detection, `per_stratum < 1`, empty seed, run-dir-outside-root, and the rank/order rule itself (I verified the last one externally against the committed sample).
6. **`texts[*].cells` means "drawn count"** — slightly ambiguous for the Phase 5 TS types; `drawn` would read better. Rename now or never, since Phase 5 will pin the shape.
