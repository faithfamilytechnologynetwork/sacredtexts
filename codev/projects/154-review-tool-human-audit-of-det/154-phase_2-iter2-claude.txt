## Non-blocking notes

1. **`excluded` sub-counts overlap.** A row that is both `cant_judge` and defect-flagged is counted in both, while `total` de-dupes — so the line reads `excluded 3 (cant_judge 2, defect 2)`. Correct, but looks like an arithmetic error to a reader. Consider "(a row can be both)".
2. **Malformed `expected` raises a raw `KeyError`.** The loader checks `expected` is a dict but not its per-task keys; `score_answer` then does `expected["text"]`. A hand-edited gold row would escape the uniform `error: …`/exit-2 path. Low risk (gold sets are machine-produced) — a per-task key check in `_validate_gold_row` would close it.
3. **Directory versions are bound to a `runs/<run>/` prefix,** so a sample drawn from a run outside `runs/` can never use one. This matches the plan verbatim; flagging only that the constraint is now baked into the gold format.
4. **Worth surfacing to the owner:** the `AR_CITE` "broken" mover encodes a human label that contradicts the sanctioned #118 rule (an *undisclaimed* echo of the form example beside the right verse — the matcher credits it, the spec's rubric treats it as two locations). The fixture documents this, and it's a legitimate construction, but it means the tool's first fixture already exhibits a rubric-vs-matcher divergence — exactly the kind of finding #41 exists to produce.
5. The smoke test calls `compare()` rather than the CLI (plan said "run the CLI once"); the CLI itself is covered by two other tests, so coverage is not actually thinner.
