**Things I checked that could have been bugs and aren't:**
- **Middleware ordering.** `mountViewer` registers `app.use('/*')` *after* the API routes, so an API handler that returns a response short-circuits before the static middleware. Confirmed by the "keeps the real API routes working with the viewer mounted" test.
- **Path traversal.** Absolute `root` + decoded-then-rechecked `..` guard in `@hono/node-server@1.19.17`'s serve-static and `hono/utils/filepath` — the library rejects both raw and percent-encoded traversal. Absolute roots are supported (the `/assets/a.js` test would fail otherwise).
- **`/runs/_index` falling through to the SPA shell.** `static.test.ts` asserts this returns `index.html` — which looked like it might break the browsing pages, but `apps/viewer/src/lib/runIndex.ts:73` *already* handles "prod static host: `/runs/_index` falls through to index.html (200 HTML) → no runs". So the README's claim that browsing pages show the "no runs" empty state is correct, not aspirational.
- **`tsx` is a runtime `dependency`, not a dev one** — so `pnpm install` under `NODE_ENV=production` won't strip the thing `pnpm start` needs. Easy trap, avoided.

## Minor observations (non-blocking)

1. **`GET /api/sample` ships 2.7 MB uncompressed with no `ETag` or `Cache-Control`.** Fine locally; on the hosted origin the viewer will re-download it on every cold page load. A one-line `ETag` off a content hash (or `hono/compress`) would be cheap. Phases 5/6 don't plan client-side caching either, so this is worth a thought before hosting.
2. **`PORT=""` resolves to port 0** (`Number("") === 0`, which is finite), so the service would bind a random port instead of failing or defaulting. `PORT=abc` correctly exits. Trivial.
3. **`parseSample` accepts `cells: []`.** A zero-cell sample starts cleanly and yields an empty pass. Defensible (the envelope check is deliberately shallow, per plan — the viewer owns the strict per-cell parse), but a `cells.length > 0` check would turn a silently-useless deployment into a startup error.
4. **The active-sample gate in `review.ts`** (save/submit 404 for a non-active id, reads/list/delete open) isn't in the phase_4 file list but is a sensible consequence of the sample arriving here, is documented in the README, and is tested. Noting it so it isn't mistaken for scope creep later.
