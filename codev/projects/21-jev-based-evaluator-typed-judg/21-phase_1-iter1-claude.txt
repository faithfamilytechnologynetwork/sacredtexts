## Issues

**1. Total spend is never surfaced (explicit spec criterion, unmet).** The spec requires spend "summed + per-cell"; `summarize()` (jev.py:456-462) returns `n`/`kinds`/`refusal_p_ge_0.5`/`judge_models`/`rubric_id` with no cost, and the CLI's post-run echo (cli.py:433-435) prints no total. Per-cell `usage.cost` is recorded, so this is a few lines in `summarize` + one echo line. (Codex found this too.)

**2. Sidecar with rows but no manifest → a silent mixed-build file.** `_load_manifest` (jev.py:256-257) returns `None` when the manifest file is absent, *without checking whether `out` already has rows*. `established[0]` then starts `None`, the first new response pins a possibly-different build and writes a fresh manifest, and the file now mixes builds — the exact outcome the spec says must never exist. Fix: in `judge`/`estimate`, if `out` exists and is non-empty while `_manifest_path(out)` does not, raise. (Codex found this too; I agree it's real.)

**3. Row schema deviates from the spec's authoritative schema.** The spec pins flat `kind` + `kind_probabilities` + `kind_confidence`; `interpret` (jev.py:176-180) emits nested `equivalence: {kind, probabilities, confidence}`. The nested form is arguably nicer (it unifies with the `"not_evaluated"` sentinel), but phase 1 owns this contract and two downstream consumers already assume the flat names: the plan's phase-2 grader registration is `Grader("jev", ("matches_requested_p","refusal_p","kind"), …)`, and phase 4's agreement module reads these rows. Either align to the spec or get the deviation ratified and update the plan's phase-2 metric keys — don't let phases 2/4 discover it.

**4. `interpret` is loose where the spec says fail loud.** `choice` is validated against `_KINDS`, but `noul` is only checked for *presence* (jev.py:155-158) — a string or bool passes through into `refusal_p`/`matches_requested_p`. And `usage` defaults to `{}` (jev.py:159), so a missing usage block silently yields `cost: None` — which is a budget control quietly reading zero. `decision_id`/`judge_provider` can likewise be `None` while the spec lists them as reproducibility fields (only `judge_model_resolved` is enforced, jev.py:183).

**5. Live smoke not done (phase-1 deliverable).** The plan's phase 1 ends with "a single-cell live smoke (≈$0.00003) … before later phases build on the HTTP/parse code," citing the hot-tier lesson that mocking the provider seam hides live-only failures. The thread (line 58) records only a *pre-flight dry run* — zero calls — and there is no judgments sidecar anywhere in the tree or in `tmp/`. The specify-phase live verification was a scratch call, not a pass through `post_decision`/`judge`, so the request body this code builds (`{"model","state","questions"}` from `build_questions`) has never hit the wire. One cell, ~$3e-5, well under the cap.

**6. Test gaps against the plan's own test plan.** `--limit` has no test at all (`grep limit pipelines/tests/test_jev.py` is empty) though the plan lists "pre-flight/`--limit` behaviour"; there's no concurrent build-conflict test (the code path via `conflict`/`established` is only exercised serially by `test_build_mismatch_on_resume_fails_fast`); no missing-manifest-resume test (issue 2); no cost-sum assertion (issue 1). The 13 tests present are well-targeted otherwise.
