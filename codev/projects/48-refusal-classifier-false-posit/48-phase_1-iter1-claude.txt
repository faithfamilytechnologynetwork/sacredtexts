## The one thing I'd fix first

**`_ASSERT_INTRO` over-fires on the canonical class-B pattern once reworded.** The real B cell `de9d77a6c963` says *"The closest I got was **a** different line from the same daf: «text»"* — it is excluded **only** because the determiner before `line` is `a` rather than `the`. That's an accident, not a principle. A one-word rewording defeats it:

```
"I couldn't find Ketubot 63b:19. The closest line I found is: «he», but I can't confirm it's that segment."
  → asserts_delivery = True  → NOT refused     # semantically pure class B
"I couldn't find the exact segment. The opening text of the daf is: «he»"
  → asserts_delivery = True  → NOT refused     # defeats the deliberate daf/begins exclusions
```

The negation guard doesn't help because `can't confirm` sits *after* the payload, outside the `clause` group. This is the spec's "Medium/High" risk (*assertion rule flips a B cell to an answer*) — mitigated for these four runs by the pin, but **unmitigated for every future run**, and `#52` builds on this function.

The fix is a direct generalization of the authors' own stated exclusions (they already drop `daf`/`segment` from `_UNIT` and `begins`/`opens` from `_VERB` because B answers describe the *surrounding* text): also reject the assertion when a **non-identity modifier** sits in the clause — `different|closest|other|another|next|previous|preceding|following|surrounding|nearby|opening|adjacent`.

I verified in-memory that this is **free**:
- all 5 A cells still read as deliveries;
- whole-corpus gate delta across all 5 (run, scores) pairs: **`[]`** — so **no committed number moves and no re-rebaseline is needed**;
- both probe cases above become `refused`.

## Non-blocking observations

1. **`_SCRIPT` is a Hebrew/Arabic/Greek allowlist**, so a hedged delivery in Devanagari, Tibetan, Han — or in **Latin script** — can never be a "payload" and stays `refused`. For Latin that means the *original bug* survives in one form: a hedge followed by a confabulated (non-containing) English/Latin delivery is still a false `refused`. Worth a docstring line (the module already warns refusal rates aren't script-comparable because of the English cue list; this is a second axis), plus a note for a future tradition that `_SCRIPT` must be extended — which brushes against arch-critical's "adding a tradition never changes core pipeline code."
2. The comment says `_SCRIPT` is "letter ranges only," but `ؠ-ۿ` (U+0620–U+06FF) also covers harakat, Arabic-Indic digits, and `٪٫٬٭`. Cosmetic, but a lone Arabic digit technically counts as a payload.
3. `test_spec48_delivered_as_answer_flips_out_of_refused` passes `{"text": ""}`, bypassing the containment half. The gate test uses real expected text, so coverage is fine, but loading the real `expected` here would be strictly stronger.
4. Minor lint: `test_outcomes.py` imports the private `_TEXT_RETRIEVAL`, and the edge-case test shadows module-level `EXP` with a local uppercase `EXP`.

Phase-boundary absorption of the tutorial rebaseline is correctly documented in the plan and the thread records the architect's explicit GO, so I'm not flagging that as scope creep.
